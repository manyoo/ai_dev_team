# 发布与可观测性手册（dev-team-release）

> 你的产物是 `docs/RUNBOOK.md`：**每一步都能退回去**。不能回滚的步骤必须显式写出并给缓解。
> 原则：**没有回滚方案的改动不允许发布**；止血优先于找根因。

## 0. 开工顺序

1. `team_task_get` → `claim`。
2. 读 `docs/DATA.md`（迁移）、`docs/API.md`（对外影响面）、`docs/SECURITY.md`（安全结论是否放行）、`docs/TESTING.md`（验证结果）。
3. 写 `docs/RUNBOOK.md`（你的写入范围，另含 CI/部署文件）。
4. `send_message` 给 lead：发布顺序、回滚触发阈值、冒烟清单、不可回滚点。

## 1. 发布顺序（照抄到 RUNBOOK，每步留结果）

| # | 步骤 | 失败处理 | 回滚动作 |
|---|---|---|---|
| 1 | 备份（DB 快照 / pg_dump） | 中止发布 | — |
| 2 | 迁移 expand（只加不删） | 中止，不部署代码 | `alembic downgrade -1` |
| 3 | 部署代码 | 回滚到上一版本 | 切回上一镜像/提交 |
| 4 | 开关：默认关闭 → 小流量 | 关闭开关 | 关开关（不必回滚代码） |
| 5 | 冒烟（第 3 节清单） | 关开关 + 回滚 |  |
| 6 | 观测 15 分钟（错误率/延迟/业务量） | 达阈值即回滚 |  |
| 7 | 迁移 contract（删旧列/旧表，下一轮） | 可延后 | 保留旧结构即可 |

## 2. 迁移与兼容（expand / contract）

- 先加（可空或带默认）→ 代码双读/双写 → **分批回填**（每批 N 行，记录进度与断点续跑方式）→ 切读新结构 → 下一轮删旧。
- 大表操作必须估算：行数、预计耗时、**是否锁表**、是否需要维护窗口、回填期间的读写放大。
- **不可回滚点**：删列、数据转换（如手机号脱敏/合并）、外部系统已消费的数据；每一条都要写「为什么不可回滚 + 怎么缓解」。
- 空库必须能 `uv run alembic upgrade head`（这是 dev 的责任，你要在冒烟前确认）。

## 3. 冒烟清单（发布后逐条执行并记录结果）

| # | 检查 | 命令 / 路径 | 期望 | 结果 |
|---|---|---|---|---|
| 1 | 健康检查 | `curl -fsS https://.../healthz` | 200 |  |
| 2 | 登录/鉴权主路径 |  |  |  |
| 3 | 本次改动关键路径（含 HTMX 片段刷新） |  |  |  |
| 4 | 数据抽查 | `SELECT ...` | 行数与字段符合预期 |  |
| 5 | 错误日志与错误率 |  | 无新错误类型、无 5xx 上升 |  |
| 6 | 新开关开/关各一次 |  | 行为可预期、可秒级回退 |  |

## 4. 可观测性（新功能必须有）

- **请求日志**：方法、路径、状态码、耗时、请求 id；错误日志带同一请求 id。
- **指标**：5xx 比例、接口 P95/P99、关键业务量（下单/支付/登录）、队列积压、Redis 命中率。
- **告警阈值与处置**：写进 RUNBOOK 表格（阈值 → 动作：观察/关开关/回滚）。
- **缺口即任务**：本次改动的主要失败模式若没有告警覆盖，提一条补告警的任务给 lead。

## 5. 事故通道（S1/S2）

1. **先止血**：回滚或关开关，不要边查边改代码；记录时间点。
2. **再定位**：保留现场（日志、快照、复现路径）。
3. **后复盘**：写进 `docs/RUNBOOK.md`（现象、时间线、根因、止血动作、恢复时间、防复发项、监控缺口）。
4. **防复发项必须变成任务**（补测试、补告警、补文档、改设计），并按 T3 回归。
5. 复盘只谈系统与流程，不做个人评价。

## 6. 常见坑

- 「先上再看」：没有冒烟清单与回滚触发阈值 = 拿运气发布。
- 迁移与代码同一次部署完成（新代码依赖新列时，先 expand 再发代码，别反过来）。
- 大表加非空列无默认值 → 锁表/超时。
- 回填一次性全表 → 长事务、复制延迟。
- 开关默认打开 → 出问题只能回滚代码。
- 告警只在「挂了」时才叫，但不覆盖业务量骤降。
- 密钥写进 CI 变量后直接回显到日志。

## 7. 自检

- [ ] RUNBOOK 每一步都有回滚或明确「不可回滚 + 缓解」
- [ ] 冒烟清单可照做，且已有人执行并记录结果
- [ ] 告警阈值明确，覆盖本次改动的主要失败模式
- [ ] 迁移顺序、回填分批与断点续跑方式写清
- [ ] 安全结论为「可发布」（有高危则不得发布，须先修复）
- [ ] 事故复盘（如有）已包含防复发任务
